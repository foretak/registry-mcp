# T63 — the publishable accuracy number

Model `claude-sonnet-5` (the harness's own `--agent`/`--baseline` default, confirmed via `evals/run.py --help`). Date 2026-09-10. Commit under test: `bdcd51e` (branch `t63`, cut from `main`; no code, fixture or `cases.json` change anywhere in this worktree — the two runs below are the only live calls). Full per-case data: `evals/reports/2026-09-10-agent-x3.md` (31 cases × 3 trials) and `evals/reports/2026-09-10-baseline-x3.md` + `.json` sidecar (15 cases × 3 trials). This page synthesizes those two; it does not repeat their row-by-row tables.

## 1. The number

**With the tools**, a Sonnet 5 agent, run three times over each of the 31 authored cases, **passed 18 of 31 outright (58%)** — the harness's own strict rule, requiring all three trials to agree before a case counts as passed. Two of the 31 are live-only smoke cases skipped by design (`E01`, `E02`); two hit a mock-coverage gap independent of the model (`E10`, `E12`, harness gaps, detailed below). Against only the **27 cases actually eligible to be scored**, that is **18/27 (67%)**. Before the strict rule is applied, the raw per-trial pass rate was **19/27 (70%)**, **23/27 (85%)**, **20/27 (74%)** on trials 1, 2 and 3 — mean **62/81 (77%)**. The 18-percentage-point spread between the best and worst trial, on the identical 27 cases with nothing else changed, is the noise the harness's three-trial rule exists to smooth; trial 2 happened to be the strongest trial in *both* arms this run (see below), which is itself a reminder that any single trial is not representative.

**Without the tools**, the same model, asked the 15 fair baseline prompts three times each (45 calls, no `tools`, no MCP `system`), was **confidently and dangerously wrong on at least one of three trials for 2 of 15 cases (13%)** — `E08` and `E20` — **honestly hedged on every single trial for 9 of 15 (60%)**, and **produced a correct-but-unsourced answer on at least one trial for the remaining 4 of 15 (27%)** — `E05`, `E06`, `E07`, `E19`. Call-by-call (the number to quote, per the same manual-audit convention `2026-09-07-baseline-run-1.md` established): **8 correct, 3 wrong (confident, dangerous), 34 honest hedge, 0 unclear**, out of 45. The auto-classifier's raw first pass, before the manual read documented in §2, was **6 correct, 7 wrong, 27 hedge, 5 unclear** — the audit moved 12 of 45 calls, all of them known failure modes this project has already named once before (below).

## 3. The E19 hard gate

**Pass rate 1/3** (trial 2 passed; trials 1 and 3 failed) — the same case DECISIONS.md D-048(i) names explicitly: *"It already fails in `--agent` mode, reproducibly and for a documented reason ... and it is kept failing on purpose."* On both failing trials the model called `search_company` to confirm Tesco PLC's identity, then answered "Companies House ... doesn't publish VAT registration data" **without ever calling `lookup_company`** — correct in substance, but never checked against this record's actual `vat_registered: null`. `search_company`'s `SearchHit` carries no VAT field at all, so the only way to answer this from the tool is to call `lookup_company` and read the null; the model instead answered from what it already knew about Companies House in general. The baseline arm finds the identical behaviour from the other side this same run: `E19`'s two `unclear→correct` baseline trials (§2) are a model stating "Yes, Tesco PLC is VAT-registered" with *no register access at all* and *no hedge* — the same confident, reasoned, unsourced answer, just without a tool available to have skipped.

## 4. What this number does and does not claim

31 hand-authored cases, every offline one running against **mocked** `tests/fixtures/*.json`, not the live Brønnøysund/Companies House/Bolagsverket registers. This is **not** a benchmark of those registers' data quality, coverage, or uptime — it is a benchmark of whether one specific model, given this specific tool surface, uses it correctly and hedges honestly when it has nothing to check against. **One model** (`claude-sonnet-5`), **one day**, **three trials**: not a cross-model comparison, and three trials smooths but does not eliminate sampling noise — this very run's `E19` swung to 1/3 where a prior investigation on the identical case (`2026-09-09-agent-after-E19-x3.md`) saw 2/3. The baseline arm's headline number is **manually audited**, not the raw auto-classifier output, because that classifier's known "genericness" blind spot (§2) reproduced five more times on fresh sampling this run alone — read `evals/reports/2026-09-10-baseline-x3.md`'s auto-classified table as a first pass, never as the verdict, exactly as `evals/README.md` already asks. **The caveat sentence a reader must carry:** this measures whether one named model, on one day, answering 31 questions someone wrote by hand against mocked data, uses this tool correctly and knows the difference between "the register says no" and "the register doesn't say" — it says nothing about a harder question, a different model, or the real registers' own accuracy.

## 5. Cost of producing it

**Baseline arm — measured**, from `evals/reports/2026-09-10-baseline-x3.json`: **45 calls, 1,281 input tokens + 19,520 output tokens = $0.20** at `claude-sonnet-5` list pricing ($2/$10 per MTok).

**Agent arm — estimated, not measured**: `evals/run.py`'s `--agent` path never reads `response.usage` anywhere in the file (confirmed by inspection — only the `--baseline` path does, which is why it alone gets a `--baseline-json` sidecar); this is a property of the harness itself, unchanged here since this worktree makes no code edits. What can be reconstructed exactly from `evals/reports/2026-09-10-agent-x3.md`: **81 completed trials** (27 scored cases × 3) making **111 tool calls** between them, implying **≈192 total API turns** (one call or one final answer per turn — every transcript this run is consistent with that, none show evidence of parallel tool calls), plus at least 2 more aborted turns on the two `GAP` cases. Costed with the README's own published method for this arm (system prompt + six tool schemas ≈ 2,000–2,500 tokens resent on every turn, no prompt caching, plus each trial's own growing message history): **≈420–450K input tokens (≈$0.85–0.90) and ≈55–60K output tokens (≈$0.55–0.60), roughly $1.40–$1.50 total** — an estimate, bounded well under the ground rules' $15 stop-threshold for both runs combined (actual combined spend, measured-plus-estimated: **≈$1.6–$1.7**), so both runs ran to completion as planned and neither needed to be cut short.

**What I could not do**: get a measured, rather than estimated, dollar figure for the agent arm — the harness has no mechanism for it in `--agent` mode, and adding one would be a code change outside this task's reports-only scope.
