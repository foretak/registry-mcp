## Goal
`registries/no/client.py` + `registries/no/mapping.py` + `core/cache.py` implementing `BrregRegistry` fully per `NORBIZ_SPEC.md`:

- HTTP via `httpx`, base `https://data.brreg.no/enhetsregisteret/api/`, 5 s timeout, one retry on 5xx/timeout, `User-Agent: registry-mcp/<version> (+https://github.com/foretak/registry-mcp; <REGISTRY_MCP_CONTACT_EMAIL>)`.
- Endpoints: `enheter/{orgnr}`, `enheter?navn=`, `enheter/{orgnr}/roller` (roles), `underenheter?overordnetEnhet=` (sub-units).
- **Field verification is mandatory:** fetch the live JSON for org.nr `833286602` (`curl` is fine), save it to `tests/fixtures/brreg_833286602.json`, and confirm every field the spec marks `VERIFY`. Fix the spec's field names in `NORBIZ_SPEC.md` if reality differs — that is the one exception to "don't touch the spec" — and note each correction in the `PROGRESS.md` done-check cell.
- `core/cache.py` — country-neutral SQLite cache (`key`, `payload`, `fetched_at`), TTL from env `REGISTRY_MCP_CACHE_TTL_SECONDS` default 86400, path from `REGISTRY_MCP_DB_PATH` default `./data/registry.db`. Report carries `cached: bool`.
- 404 → `RegistryError(code="not_found", hint="Check the orgnr with validate_company_id; ...")`.
- `scripts/lookup_demo.py` prints a `CompanyReport` for 833286602.
- Tests with `respx` using the fixture: lookup maps every field; 404; 5xx retried once then error; timeout; cache hit on second call sets `cached=True`; TTL expiry refetches.
