# T01 — Interface, models, and the Norwegian spec

Owner: Opus A (architect)
Depends on: nothing
Unblocks: T02, T03, T04, T05

## Goal

Define the shapes everyone else builds inside. Two deliverables:

1. **`NORBIZ_SPEC.md`** — the technical spec for the Norwegian module. The original spec file was never delivered, so you write it from the build plan (`BRREG_MCP_BUILD_PLAN.md`) plus your own knowledge of Brønnøysundregistrene's open API (`https://data.brreg.no/enhetsregisteret/api/`). It must contain, at minimum:
   - The `CompanyReport` field list with types and which brreg field each one comes from (mark any you are not certain of as `VERIFY` — T03 will check against the live JSON for org.nr `923609016`).
   - Rules: MOD11 orgnr validation (weights 3,2,7,6,5,4,3,2; remainder handling; reject 10 → invalid), org-form mapping (at least AS, ASA, ENK, ANS, DA, NUF, SA, STI, KS, BA, FLI, KF, IKS with an English label and whether it has a board/annual-accounts duty), status derivation (active / dissolved / under liquidation / bankrupt / deleted, from `konkurs`, `underAvvikling`, `underTvangsavviklingEllerTvangsopplosning`, `slettedato`), and the Norwegian filing deadlines a company in each org form faces (annual accounts to Regnskapsregisteret 31 July, tax return / skattemelding 31 May, MVA bimonthly terms on the 10th of the second month after term end, aksjonærregisteroppgave 31 Jan, plus any others you're confident about). Deadline calculation takes `today: date` as a parameter and rolls weekend/holiday-free dates forward to the next weekday.
   - A **numbered test list** for the rules (each test = one line: input → expected). T02 implements exactly this list.
   - Client behaviour: 5 s timeout, one retry on 5xx/timeout, descriptive `User-Agent` including a contact email from env `REGISTRY_MCP_CONTACT_EMAIL`, 404 → `RegistryError(code="not_found")`, SQLite cache with 24 h TTL, `cached: bool` on the report.
   - Error format: `{"error": {"code": str, "message": str, "hint": str}}` where `hint` tells an agent what to do next.
   - Logging: one function that records every REST and MCP call (timestamp, surface, tool/endpoint, country, query, user agent, latency, ok/error) to SQLite.
   - Confidence scale: how `confidence` on a report/search hit is expressed (recommend a small enum or 0–1 float — decide and record in DECISIONS).
2. **The core interface** with docstrings and minimal implementation:
   - `core/models.py` — `CompanyReport`, `Deadline`, `SearchHit`, `RegistryError` (pydantic v2). Country-neutral. Every model carries `country: str` (ISO-2, upper) and `registry: str` (e.g. `"brreg"`).
   - `core/registry.py` — abstract `Registry` with `lookup(id)`, `search(name, limit)`, `validate_id(id)`, `deadlines(report, today)`, plus a registry **registration mechanism** keyed by country code (`register("NO", BrregRegistry)`, `get_registry("NO")`, `list_countries()`).
   - `core/rules/__init__.py` and `core/rules/common.py` — signatures only for `next_weekday(d)`, `next_occurrence(month, day, today)`, `roll_forward(d)`; T02 implements bodies.
   - `registries/xx/` — a stub second-country registry proving a new country is one folder with no `core/` edits.
   - `registries/no/__init__.py` — stub `BrregRegistry(Registry)` that raises `NotImplementedError`, registered under `"NO"`.
3. **Project packaging** — `pyproject.toml` (Python ≥3.12, `uv`-managed, deps: `pydantic`, `httpx`, `fastapi`, `uvicorn`, `fastmcp`; dev: `pytest`, `pytest-cov`, `ruff`, `mypy`, `respx`), `ruff.toml`/`[tool.ruff]`, `[tool.mypy]` strict, `README.md` stub, `LICENSE` (MIT, holder "Kim").
   **You must resolve the layout problem:** the guide asks for top-level `mcp/`, which shadows the `mcp` PyPI package that FastMCP imports. Recommended: `src/registry_mcp/{core,registries,api,mcp}/` so subpackages never shadow. You may move the current skeleton dirs. Record the decision.
