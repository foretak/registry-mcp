## What is wrong

`api/main.py::_record` and `mcp/server.py::_call_context` pass the caller's raw identifier to
`core/log.py::log_call` as `query`, which writes it to the `calls` table and keeps it for the life
of the service. For `NO` and `GB` that is a company number. For `SE` a sole trader's identifier
**is their personnummer**. Bolagsverket designed its API as POST-on-read to keep that number out
of logs; we would put it back into one — and, via uvicorn's default access log, into Railway's
log stream as well.

## The change

1. **`core/registry.py`** — `id_may_be_personal: ClassVar[bool] = False` on `Registry`, docstring
   per D-040(a). Module-level `loggable_query(country, query)` per D-040(b): resolve with
   `get_registry(country, include_stubs=True)` inside a `try`; unresolvable → return `query`;
   flagged → `None`; else `query`. Pure, never raises. While there: **F2** — the docstring example
   `id_example = "5560212524"` at the top of the file is not a valid organisationsnummer; replace with
   `"5560160680"` (`SWEDEN_SPEC.md` §0 F2).
2. **`registries/se/__init__.py`** — `id_may_be_personal = True` beside `requires_api_key`. One line.
3. **`api/main.py::_record`** — `query=loggable_query(country, query)`. No route changes.
4. **`mcp/server.py::_call_context`** — same, inside the `finally`. No tool changes.
5. **`mcp/connector.py`** — `fetch` logs `country` = the parsed prefix and `query` = the bare
   identifier (both through the helper; today it logs `country=None, query="SE:…"`). `search` logs
   its text through the helper with the country `_derive_country` returned (None if none). The
   `_call_context` signature may grow whatever it needs (e.g. the outcome object carrying
   `country`/`query` overrides set after parsing) — your call, keep it small.
6. **`Dockerfile`** CMD — add `--no-access-log` to the uvicorn invocation (D-040(e)). Leave the
   stdio branch alone.
7. **`legal/privacy.md`** — one sentence in "Your request", per D-040(f). Nothing else on that page.
