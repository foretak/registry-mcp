## Why Ireland, and why it is an override

The standing research order is **Sweden → Finland → Ireland** (`PROGRESS.md` R02). Ireland ahead
of Finland is a deliberate override and the reasons are on the record
(`~/research/registry-mcp/02-registers-landscape/08-ireland-cro.md`):

- **English-native.** Ireland, the UK and the US are the only English-native registers in the
  survey. No legal-form translation table, no local-language `status_detail`, and a contributor
  can extend the module without help — which is what `content/04-add-your-country` recruits for.
- **CC BY 4.0 daily bulk, with parsed financial statements alongside it.** The research calls
  this "close to best-in-class — only Estonia matches it".
- **A published Annual Return Date.** If the ARD is in the free data, Ireland becomes the
  **second** country able to fill `published_deadlines`, which stops that field being a UK
  special case and validates D-018's shape across two registers. This is the single most
  valuable unknown in §T27r and the reason Ireland is worth doing before Finland.
- The UK module already models strike-off, so the status ladder is largely built.

## The architectural ruling that must not be got wrong

**Open Services (the live API) is the route. The CC BY 4.0 bulk CSV is for fixtures and field
discovery only, and must never become the serving path.**

A mirrored dataset is precisely what CompanyLens does — *"indexed in CompanyLens's own database…
no dependency on upstream registry availability"*
(`~/research/registry-mcp/05-competitors/04-multi-country-and-gleif-mcp-servers.md`) — and
`README.md` sells the opposite: *"Never more than 24 hours stale, and it says so."* A country
served from a nightly CSV would carry a `fetched_at` that means something different from every
other country's, which is D-004's whole objection to surface-specific shapes, one level up. If
Open Services turns out to be unusable, that is a finding for Opus A and a `DECISIONS.md` entry,
**not** a quiet swap to the bulk file.

## Ground rules

`tasks/T26.md` §"Ground rules" applies verbatim, with `se`→`ie`, `SE`→`IE`. In short: everything
Irish in `src/registry_mcp/registries/ie/`; `country = "IE"`, `registry = "cro"`; one import line
in `registries/__init__.py` (alphabetical: gb, ie, no, se, xx); **zero edits to `core/`, `api/`,
`mcp/`** — a needed edit is the finding, not a patch. Unknown is `None` (D-004/D-009/D-011).
Every deadline ships only with a primary-source citation or not at all (D-016/D-023). No
production calls to `api.foretak.dev`; never look up `833286602`. No agent commits; no agent
edits `PROGRESS.md`.

One Ireland-specific rule: **`services.cro.ie` returns 403 to automated fetches.** Use Wayback
captures, the CKAN APIs (`opendata.cro.ie` and `data.gov.ie`, both of which answered anonymously
on 2026-09-05), GitHub/npm/PyPI code that already talks to Open Services, and `irishstatutebook.ie`
for the Companies Act 2014. Sweden's trick is worth trying first: a desktop Chrome `User-Agent`
plus `Accept-Language` defeated Bolagsverket's bot protection, which keyed on headers, not IP.

## Sub-tasks

### T27r — Recon (Opus R): the facts the spec cannot invent

Runs **first**, or in parallel with T27a with the same `VERIFY-pending-recon` protocol T26a used.
Output: (1) `~/research/registry-mcp/02-registers-landscape/08b-ireland-api-shape-and-law.md` in
library format (source, publisher, published, fetched, confidence, verbatim quotes), and (2) an
implementer-facing digest `tasks/T27-recon.md` with the same facts, confidence-tagged
(**[H]** primary read directly · **[M]** secondary · **[L]** inferred), no prose padding.

Find, in priority order:

1. **Is the Annual Return Date in the free data?** Both routes: the "Company Records" CSV
   (download it — it is CC BY 4.0 and needs no signature) and Open Services. Record the exact
   column/field name, its format, and whether it is the *next* ARD or the last one filed. If it
   is there, also find whether the CRO publishes a filing deadline derived from it (the 56-day
   rule) or only the ARD itself — the distinction decides whether Ireland fills
   `published_deadlines` (quote the register) or computes (cite the statute), which is D-018's
   line. **This is the highest-value fact in this task.**
2. **The Open Services API shape.** Endpoint base, transport (REST/JSON or SOAP — do not assume),
   the operations, request and response field names, error shape, and how a company number is
   passed. Sources to try: the CRO's own Open Services page via Wayback, GitHub code search for
   `services.cro.ie` / `cro.ie/api` (`gh api search/code` is authenticated), npm and PyPI
   packages naming the CRO, and any published code examples — the CRO states it publishes them.
3. **The Terms & Conditions text and the licence it imposes.** The research flagged this unread.
   It decides the `license` string for `IE` and whether we may relay the data at all. The bulk
   route is `CC-BY-4.0` on both `opendata.cro.ie` and `data.gov.ie` (attributed to the Companies
   Registration Office); the Open Services T&Cs are a separate instrument and **must not be
   assumed to match**. If the text cannot be retrieved, say so and record what may be quoted
   safely in the meantime — a `license` we cannot source is `None`, not a guess.
4. **Rate limit.** The Open Services pages state none. Confirm or refute from a primary source;
   if genuinely unstated, record that and the client ships a conservative self-imposed bucket
   with a comment saying it is ours, not theirs.
5. **The CRO number.** Confirm or refute "plain sequential integer, six or seven digits, no
   check digit, not zero-padded". If there is no check digit, `validate_id` does shape only and
   **must say so** — D-021's `id_caveat`, exactly as Sweden's `validate_company_id` does, so an
   agent is never told a shape-check is an existence-check (D-013). Also: the relationship, if
   any, to the tax reference / VAT number (`IE` + 7 digits + 1–2 letters), which the research says
   is **not** derivable — confirm, because an agent will ask.
6. **Code lists**: company type / legal form codes, and the company status ladder including the
   strike-off states (and whether "strike-off listed" and "struck off" are distinct codes). Map
   each onto `CompanyStatus`; anything that does not map cleanly belongs in `status_detail` and
   `notes`, never forced into an enum member.
7. **Statutes for deadlines**, from `irishstatutebook.ie`: the Companies Act 2014 sections for
   the annual return and for financial statements — the exact section numbers and wording, the
   period, and any late-filing penalty scale. **Find whether Ireland applies a weekend/holiday
   roll-forward**; if no rule is found, ship none (Sweden's precedent, D-022).
8. **Whether the two routes agree.** If Open Services and the CSV disagree on a field's value or
   name, that is worth a paragraph: it decides whether the CSV is usable for fixtures at all.

Done-check: both files exist; every fact carries URL + fetch date + confidence; a
"could not be verified" list at the end; the Company Records CSV actually downloaded and its
header row recorded verbatim; **no production calls; no signed agreement entered into.**
