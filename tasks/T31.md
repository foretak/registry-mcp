# Part A — the sentence is false, and it ships in the tool description

## What is wrong

`SWEDEN_SPEC.md` §5.4 concluded that *"Bolagsverket's free dataset does not publish the financial
year"* and built both Swedish deadlines on an assumed 31 December year end. **It does publish it.**
`POST /dokumentlista` — same API, same credential, same `vardefulla-datamangder:read` scope —
returns per filed annual report:

```json
{"dokumentId": "02f54e4f-…_paket", "filformat": "application/zip",
 "rapporteringsperiodTom": "2022-12-31", "registreringstidpunkt": "2023-06-27"}
```

`rapporteringsperiodTom` is the reporting period's last day: the company's own financial year end.
`registreringstidpunkt` is when the filing was registered. Both are `format: date` in the OpenAPI
document (`~/research/registry-mcp/02-registers-landscape/02b-sweden-openapi.json`, schema
`DokumentlistaSvar_dokument_inner`); the item above is real, from Bolagsverket's own test workbook,
recorded at `tasks/T26-recon.md` line ~100.

A *brutet räkenskapsår* is lawful, so a company with an April year end is currently told 30 June and
31 July when its own dates are four months later. Part A does not fix the date. It fixes the
**reason we give for not having it**, which is currently a false statement about a public register,
published in the description an agent reads before it calls `company_deadlines`.

## The change (Part A)

Replace the claim *"the register does not publish it"* with the true one, *"this module does not
read the document list that would show it"*, everywhere. Keep every other clause — the outer-limit
caveat and the nine-month variant are unaffected and must survive verbatim (D-041(f)).

# Part B — `include=["filings"]` (do not start until R-5 has landed)

**Preconditions, verify all three before starting.** `core/models.py` defines `SourceRef`
(D-026(c)); `lookup_company` accepts `include: list[str] = []` with a closed set, an unknown value
raising `bad_request` naming the allowed set; `core/cache.py`'s per-kind TTL table exists
(`_ttl_seconds`, ~`core/cache.py:84-94`). If R-5 shipped `include` on `lookup_company` only,
extending it to `company_deadlines` is part of this task (D-041(b)).

## 1. `core/models.py` — two models and one field

Shapes are given in D-041(d) and are not to be widened. Field descriptions must carry, in substance:

- **`FiledDocument.kind`** — the `Deadline.kind` slug this filing discharges. `/dokumentlista`
  returns annual reports only, so Sweden always sets `"annual_accounts"`; it is a slug and not an
  enum so a register with more document types fits without a reshape.
- **`FiledDocument.period_end`** — the reporting period's last day, as the register published it.
- **`FiledDocument.period_start`** — `None` for Sweden: Bolagsverket publishes no `...From`
  counterpart. The field exists because Norway's Regnskapsregisteret publishes
  `regnskapsperiode: {fraDato, tilDato}` (D-023(c)) and will fill it.
- **`FiledDocument.days_from_fee_point`** — signed; negative means filed before the datum. The datum
  is **seven months after `period_end`, årsredovisningslagen 8 kap. 6 §**, and the description must
  name it, must say it is not the company's actual filing deadline (8 kap. 3 § runs from an AGM date
  nobody publishes), and must say the nine-month variant of 8 kap. 6 § cannot be excluded from this
  dataset. `None` when either input is missing. **There is no `filed_late` boolean** — D-041(d)
  declined it and D-011/D-028(3) are why.
- **`FiledDocument.document_id` / `file_format`** — opaque upstream handle, not fetchable through
  this API; `filformat` is a MIME type despite the name.
- **`FilingHistory.financial_year_end`** — a real `date`, carried verbatim: the `period_end` of the
  most recently filed annual report (ties broken by the later `filed_at`). Never a synthesised
  month-day. Description must say it is **evidence of** the current financial year, not a statement
  of it — a company may relay its räkenskapsår.
- **`FilingHistory.provenance: SourceRef`** — required, not optional. `fetched_at is None` inside a
  present block means no request was made; `notes` says why.
- **`CompanyReport.filings: FilingHistory | None = None`** — always present per D-004, `null` on
  every country not asked. The two-level nullability is the contract and must be tested as such
  (D-041(c)): **absent** = not requested, or the fetch failed (with a `notes` sentence saying which);
  **present with `documents: []`** = Bolagsverket holds no filed annual report for this entity.

**Do not touch `published_deadlines` and do not fill `last_annual_accounts_year` for Sweden.**
D-041(c) rules both: a second-round-trip value never lands on a first-round-trip field. Sweden's
`last_annual_accounts_year` stays `None` permanently, and the `SWEDEN_SPEC.md` §2 mapping line
(~line 490) changes from `DEFERRED` to a permanent "`None` — by design, D-041(c)".

## 2. `registries/se/client.py` — the second call

- `_post_dokumentlista(base_url, token, identitetsbeteckning)` mirroring `_post_organisationer`
  exactly: same one-retry-on-timeout-or-5xx, same **fresh** `X-Request-Id` UUID4 per attempt logged
  at DEBUG (**the request id, never the body**), and it **spends a token-bucket token** — it is a
  real request against the published 60/min (`SWEDEN_SPEC.md` §1.5; `x-throttling-tier: "Unlimited"`
  in the OpenAPI is a WSO2 gateway artefact and repeals nothing).
- Wrap it in the same one-time token-refresh-and-retry on 401/403 that `_fetch_organisationer` has.
- **Response handling is *not* `/organisationer`'s** (D-041(h)): `DokumentlistaSvar` is
  `{"dokument": [ … ]}` — a plain array of plain objects with **no `dataproducent`/`fel` wrapper**.
  Do not point the `fel`-inspecting helpers at it. A 200 means the answer arrived.
- `dokument` is **not** in the schema's `required` list: an absent key and an empty array both mean
  the same thing — a present block with `documents: []`. **Never `not_found`.**
- **A filings failure never fails the lookup.** Any error on this call leaves `filings` absent and
  appends one `notes` sentence saying the document list could not be fetched. `/organisationer`
  decides whether an entity exists; `/dokumentlista` never does.
- Status mapping for this endpoint: 400 → `invalid_id` (the identifier is the only input);
  401/403 → the existing unauthorized path; 5xx/timeout → `upstream_error`/`upstream_timeout` — but
  see the bullet above: those are swallowed into the absent-block-plus-note path, not raised.
  **A 400 on `GET /dokument/{dokumentId}` would be `upstream_error`, never `invalid_id`** — that
  operation takes no identifier, and the shared 400 example's *"Identitetsbeteckning har ogiltig
  kontrollsiffra."* is a documentation bug on Bolagsverket's side. Do not code to the `detail`
  string anywhere.
- **Cache:** key `SE:bolagsverket:filings:{short_env}:{identitetsbeteckning}` following the existing
  `_cache_key` convention. TTL **24 h for a non-empty list, 1 h for an empty one** — D-006's
  positive/negative asymmetry for D-006's own reason (D-041(h)). Register the `filings` kind in
  `core/cache.py`'s per-kind TTL table; do not add a second TTL mechanism.
- The fetch is **unconditional** when `include=["filings"]` is passed — no legal-form gate
  (D-041(g) declined it and says why).

## 3. `registries/se/mapping.py` — build the block

Map `dokument[]` → `FiledDocument`, sorted by `period_end` descending then `filed_at` descending.
`kind="annual_accounts"` on every item. `financial_year_end` = the first item's `period_end`.
`days_from_fee_point` = `(filed_at - (period_end + 7 months)).days`, `None` if either is missing.
`provenance` = a `SourceRef` carrying the same `source` / `source_url` / `license` strings the
report uses (§1.9) with **its own** `fetched_at` and `cached` — that independence is the whole point
of D-041(c) and must be visible in a test where the report is a cache hit and the block is not.
The test-environment note (N10) applies to this block's `source` too.

## 4. `registries/se/rules.py` — the second rung

`deadlines_for(report, today)` stays **pure** (D-018) and reads `report.filings`, exactly as
`registries/gb/rules.py:642` reads `report.published_deadlines`. The ladder becomes:

1. a `published_deadlines` entry — still unreachable for Sweden, still implemented (see Part A item 8);
2. **`report.filings.financial_year_end` is present → compute from its month and day;**
3. the calendar-year assumption → 30 June / 31 July, as today;
4. nothing.

**Rung 2 is gated on a `VERIFY` and you must do the reading before you emit a non-December date**
(D-041(e)): ABL 7 kap. 10 §'s *"inom sex månader från utgången av varje räkenskapsår"* and ÅRL
8 kap. 6 §'s *"inom sju månader från räkenskapsårets utgång"* do not settle whether a 30 April year
end gives **30 October** (same day of month) or **31 October** (end of the sixth month). Both
readings give 30 June and 31 July for a 31 December year end, which is why nothing shipped depends
on it. Read **Bolagsverket's own published table of *sista dag för årsstämma* and *sista dag att
lämna in årsredovisningen* by räkenskapsårsslut**, cite it in the code comment and in
`SWEDEN_SPEC.md` §5.4, and implement what it says. **If you cannot source it, ship Parts B.1–B.3 and
leave rung 2 out** — the block is still worth having, the deadline stays on rung 3, and N9 says the
year end is known but not yet computed from. Report that outcome; do not guess the arithmetic.

Per-deadline fields on rung 2: `period_end` = the applicable financial year end (the observed
month/day, in the year the next due date belongs to); `period_start` = **`None`** (D-041(e): pairing
a known end with a start derived by subtracting twelve months asserts a period length the register
never stated, and bokföringslagen 3 kap. 3 § permits an 18-month first or final period);
`period_label` = the ISO year-end date, not a bare year. `statutory_date == due_date` and
`rolled_forward is False` are **unchanged** — D-022(b), and §5.3 found no Swedish source either way.
`core/rules/common.py::last_day_of_month` already does the day clamping you need; `next_occurrence`
takes a month and a day and clamps, so 29 February is handled.

`applies_because` on rung 2 names the observed year end, the period it came from, **and** the date
that filing was registered — *"…computed from the financial year end Bolagsverket's document list
shows for this company's last filed annual report (period ending 2022-12-31, registered
2023-06-27)"* — so an agent can see both the fact and its age. The ÅRL 8 kap. 3 § outer-limit clause
and the nine-month clause stay on rung 2 as well as rung 3.

## 5. N9's three states (D-041(f))

- **Block absent** → Part A's corrected text, **plus one sentence naming the call**:
  `include=["filings"]` replaces the assumption with the register's own figure. A note that
  discloses an assumption without naming the call that ends it is half a note (D-007's hint rule).
- **Block present, year end 31 December** → not an assumption but a **confirmation**: name the
  observed period end and its filing date. The word "assum" must not appear.
- **Block present, year end not 31 December** → the same confirmation plus the caveat that actually
  applies: a company may relay its räkenskapsår (bokföringslagen 3 kap.), and only the period *end*
  is published, so a shortened or extended period is invisible to us.
- **Surviving every state:** ÅRL 8 kap. 3 §'s one-month-after-the-AGM clause and 8 kap. 6 §'s
  nine-month variant. Neither has anything to do with the calendar year — do not drop them.
