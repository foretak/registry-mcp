## 1. The payment-fraud caveat reaches `instructions` (finding 5(a))

`mcp/server.py` `instructions` (~lines 169–178) carries the pitch — "Check whether a company you're about to
deal with … is real, active and keeping up with its statutory filings" — with no caveat, while the
`counterparty_check` prompt (~line 730) says "it is not a defence against payment fraud". `instructions` is
the string every MCP client puts in front of the model. Add **one sentence, in the same clause as the pitch**,
in the prompt's own words: this service does not screen sanctions, PEPs or adverse media, does not verify bank
details, and is not a defence against payment fraud — the commonest invoice fraud is a real, active supplier
impersonated. Then **hoist the caveat to one module constant** used by both the prompt and `instructions`, so a
third use cannot paraphrase it (finding 5's own suggestion). `test_counterparty_check_prompt_states_what_it_does_
not_establish` must stay green unchanged; add one test that `instructions` contains the constant.

## 2. An internal error is not a successful call (finding 6, `mcp/server.py` half)

exception escaping a tool body is logged to the usage table as a success. Add `except Exception: outcome.ok =
False; raise` (or the equivalent that keeps the D-007 envelope behaviour for `RegistryError` exactly as it is)
in `_call_context`, and a test that a tool body raising `RuntimeError` is recorded with `ok=False` and still
raises. Read `tests/test_mcp.py`'s existing `_call_context`/outcome tests first and follow their fixture style.
**Do not** touch `core/registry.py`'s misconfiguration guard — that is T42's.
