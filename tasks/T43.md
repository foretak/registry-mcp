Field descriptions must carry, in substance:

- **`participant_id`** — the ISO 6523 participant identifier, `"0192:" + normalised orgnr`, where
  `0192` is Norway's ICD for the organisasjonsnummer. **Derived offline and always populated, even
  when every lookup failed** (D-029(c)): it is the key the caller needs to ask elsewhere.
- **`registered`** — three states and the description must give all three, because this is the field
  an agent branches on under a statute: `true` = the Peppol network answered for this participant;
  `false` = **the authoritative SML/SMP route answered that it is not registered**; `null` = we could
  not get an authoritative answer, *including when the Peppol Directory simply did not list them*,
  which the Directory's own operators say means nothing (D-046(a)).
- **`can_receive_invoice`** — derived by exact membership of a committed table of document type
  identifiers (§C4), not by matching text. `true` means the SMP advertises the Peppol BIS Billing 3.0
  Invoice document type (DFØ: *"Peppol BIS billing v3.0 er det samme som EHF-faktura"*), which is the
  1 January 2027 question. It must also say that the SMP publishes per-document-type activation and
  expiry dates that this block does not read, so an advertised type may be future-dated or expired.
- **`document_types`** — the **document type** identifiers the answering SMP advertises, full
  qualified `"<scheme>::<value>"`. Not process identifiers (those live one HTTP call deeper, per
  document type, and are not carried — D-046(e)). Only *receiving* capabilities are registered
  anywhere in the Peppol network, which is the right semantics for "can this counterparty receive".
- **`smp_url`** — the SMP base URL **the SML named for this participant**, verbatim. The description
  must say that this varies per participant and is never assumed: ELMA is not the only Norwegian SMP.
- **`provenance`** — a `SourceRef` describing the fetch that produced the answer. `source` names the
  SMP host and the route, derived, never a constant. `license` is the stated absence in D-046(g),
  quoted exactly. One `SourceRef` for the whole block even though two round trips were made: the DNS
  step only located the host and is disclosed as `smp_url` (D-046(d)).

## C. `registries/no/peppol.py` (new)

The module holds the resolver call, the HTTP client, the mapper, the cache read/write and the
committed table — the same separation `registries/*/client.py` uses. Its docstring must say that the
**TTL is registry-mcp's own policy and neither upstream publishes one** (both send `no-store`; the
NAPTR TTL is 60 seconds).

### C1. Step 1 — the SML, and it is DNS

```
NAPTR  <base32(sha256(lower(value)))>.iso6523-actorid-upis.participant.sml.prod.tech.peppol.org
```

- The hash is over the **identifier value only** — `"0192:923609016"` — **not** over the qualified
  `"iso6523-actorid-upis::0192:923609016"`. The scheme is a separate DNS label. Lowercase first,
  SHA-256, Base32, **strip trailing `=`**. Six lines of stdlib, no network, no dependency:
  `base64.b32encode(hashlib.sha256(pid.lower().encode()).digest()).decode().rstrip("=")`.
  Two vectors, both reproduced offline while writing this brief — pin them both as unit tests:

  | participant id | label |
  |---|---|
  | `0010:5798000000001` (the SML spec's own worked example) | `XUKHFQABQZIKI3YKVR2FHR4SNFA3PF5VPQ6K4TONV3LMVSY5ARVQ` |
  | `0192:923609016` (Equinor) | `XQK4T3FMTEZDUY5BOVJMTNAQ45N7E4TIBYHWFPGOT75BSP7UYG2A` |

- **The zone is a module constant with its citation** — `participant.sml.prod.tech.peppol.org`,
  Peppol SML v1.3.0, valid from 2025-11-01. **The SMP host is not.** See "The one trap" below.
- Take the record whose service field is **`Meta:SMP`** and whose flag is `U`; the base URL is the
  substring between the second and third `!` of the `!.*!<url>!` regexp. Equinor's answer, verbatim:
  `100 10 U Meta:SMP !.*!https://smp.elma-smp.no/! .` (TTL 60).
- **Use `dns.asyncresolver`, never the synchronous `dns.resolver.resolve`** — both surfaces are
  async and a blocking resolve stalls the event loop for every concurrent request. Set an explicit,
  short timeout/lifetime; `lookup_with` runs attachments concurrently and a hung DNS read must not
  hold a lookup open.
- **Put the resolver call behind one module-level function** (e.g. `async def _resolve_smp_base(...)`)
  so tests can monkeypatch it. `respx` mocks `httpx` and cannot see `dnspython`; the HTTPS steps stay
  `respx`-mocked and the DNS step is patched at this seam.
- **Outcome mapping, and this is where `false` is won or lost (D-046(c)):**

  | Resolver outcome | Result |
  |---|---|
  | an answer with a `Meta:SMP` `U` record | go to C2 |
  | **NXDOMAIN** | `registered: false` — the participant is in no SMP. **This and an SMP 404 are the only two things that earn `false`** |
  | NOERROR with no `Meta:SMP` record | `registered: null` + note, **never `false`** — this is what a filtering or NXDOMAIN-rewriting middlebox produces |
  | timeout, SERVFAIL, no nameservers, any other exception | `registered: null` + a note naming the DNS step, then the C3 fallback |

  **A resolver exception is not an NXDOMAIN.** Map the library's exception types explicitly; do not
  catch `Exception` and infer.

### C2. Step 2 — the SMP

`GET <base>/iso6523-actorid-upis%3A%3A0192%3A<orgnr>` → the ServiceGroup XML.

- **Percent-encode the colons in the path segment** (`%3A%3A` and `%3A`), as shown.
- **Join with care: ELMA's NAPTR URI ends in `/` and Conta's does not.** Strip one trailing `/`
  before joining, and assert both forms in tests.
- `document_types` = every `ServiceMetadataReference/@href`, split on `/services/`, take the tail,
  percent-decode → a full `"<scheme>::<value>"` string. Equinor returns **17**; the modal Norwegian
  participant returns **2** (89.4% of a 500-participant sample) and one in the sample returned 26.
  **No cap and no truncation** (D-046(e)).
- HTTP 200 → `registered: true`. HTTP **404** → `registered: false`, with `smp_url` still populated
  (the SML did answer — that is worth returning). Any other status, or a transport failure → `null`
  + note, then the C3 fallback.
- No client certificate, no token, no mutual TLS: a bare GET returns 200. The Peppol certificate
  appears only *inside* the answer as an XMLDSig signature; **this task does not verify it** — say so
  in the module docstring so the next reader knows it was considered and skipped, not missed.
- **HTTPS only.** `http://smp.elma-smp.no/…` returns 503; SMPs became HTTPS-only on 2026-02-01.

### C3. The fallback — the Peppol Directory, positive answers only

`GET https://directory.peppol.eu/search/1.0/json?participant=iso6523-actorid-upis::0192:<orgnr>`

- **Only when C1/C2 produced no answer at all.** Not after an NXDOMAIN (that is already the answer),
  not after a ServiceGroup (that is a better one). D-046(a).
- **The scheme must be part of the `participant` value.** A value that will not parse as a
  participant identifier is *silently ignored*, and if it was the only term the request 400s.
- An empty result is **HTTP 200 with `"total-result-count": 0`**, never a 404.
- A non-empty match → `registered: true`, `document_types` from `matches[0].docTypes[]` joined
  `"<scheme>::<value>"`, and a `notes` sentence saying the answer came from the Directory, which is
  an index of the network that may lag — measured: Equinor's SMP advertises 17 document types and the
  Directory lists 12.
- **An empty result → `registered: null`, never `false`**, plus a `notes` sentence carrying the
  operators' own reason: publication to the Directory is voluntary and an absence there does not mean
  the entity is not in the Peppol Network.
- **`contact` is never requested, never read, never mapped, never logged and never relayed**
  (D-046(f)) — no model field, no mapper branch, and the `contact=` query parameter is never sent. It
  is the only place personal data lives in any of these payloads, and the Directory's Privacy Policy
  restricts personal data to contractually authorised Peppol users, which we are not. Put the reason
  in a comment; a done-check greps for it.
- Do not carry `name`, `websites`, `regDate` or `countryCode` onto the block — a second register's
  opinion of a company we have already described (D-046(e)).

### C4. The committed table and `can_receive_invoice`

A module-level `frozenset` of **document type identifiers**, cited in a comment, matched by **exact
string equality on the full `"<scheme>::<value>"` form** — never a substring, never a version range:

```
busdox-docid-qns::urn:oasis:names:specification:ubl:schema:xsd:Invoice-2::Invoice##urn:cen.eu:en16931:2017#compliant#urn:fdc:peppol.eu:2017:poacc:billing:3.0::2.1
peppol-doctype-wildcard::urn:oasis:names:specification:ubl:schema:xsd:Invoice-2::Invoice##urn:peppol:pint:billing-1::2.1
```

The first is BIS Billing 3.0 Invoice = EHF faktura (DFØ), advertised by 384,834 of 385,268 Norwegian
participants; the second is its PINT successor (3.4%). **The CreditNote id is deliberately not in
this table** — the flag is named for the invoice and the credit note is in `document_types` for
anyone who needs it.

| `registered` / route | `can_receive_invoice` |
|---|---|
| `true`, via the SMP | `True` if a table id is in `document_types`, else `False` |
| `true`, via the Directory | `True` if a table id is present; **`None` otherwise — never `False`** |
| `false` | `False` |
| `null` | `None` |

The Directory row is not an oversight: a Directory list is a **subset** of the SMP's, so presence is
sound and absence is not (D-046(e)).

### C5. Provenance, notes and cache

- **`provenance.source` is derived** — the SMP host that answered plus the route (`"smp.elma-smp.no
  (Peppol SMP, via the Peppol SML)"` in shape), or the Directory named as an index that may lag.
  **A constant here is a defect.** `source_url` is the exact URL fetched. `fetched_at` is the moment
  of the HTTPS read (D-046(d): the DNS step located the host, it did not produce the answer).
- **`provenance.license`** is D-046(g)'s stated-absence string, quoted exactly. Do not write "NLOD",
  do not write "CC BY", do not write `None`.
- **`notes`**, route sentence first, then: that only *receiving* capabilities are registered in the
  Peppol network; that per-document-type activation/expiry dates exist at the SMP and are not read;
  on the Directory route, the lag and the voluntary-publication caveat; on a `null`, which step
  failed. Keep it to what a caller must know to read the block correctly.
- **Cache.** Key `NO:brreg:peppol:{orgnr}` — four segments, kind third, beside the
  `NO:brreg:entity:{orgnr}` and `NO:brreg:filings:{orgnr}` keys `registries/no/client.py` already
  builds. Cache the **composed answer** and nothing else: `true` at the ok TTL, `false` through the
  existing `status="not_found"` path at the empty TTL, and **`null` is never written to the cache at
  all**. **Never cache the NAPTR→SMP binding** — its own TTL is 60 seconds and D-046(b) rules the
  host is read fresh.
- A transport failure that leaves us with nothing at all raises `RegistryError(UPSTREAM_ERROR)`;
  `lookup_with` turns that into an **absent** block plus a `notes` sentence on the report, and the
  lookup still succeeds (D-042(b)). Note the distinction: an *unanswered* Peppol question is a
  present block with `registered: null`, because `participant_id` is always worth returning; only a
  failure that prevents building the block at all is an absent block.

## The one trap

**Hardcoding a host — either of the two, and both are one mistake.**

1. **`smp.elma-smp.no`.** It works for **42 of 43** Norwegian participants tested, which is exactly
   why you would do it and exactly why your tests would pass. Digdir says in writing that a
   lookup only in ELMA is not a valid way to look up Norwegian organisations, and the 1-in-43
   (`0192:837056942` → `smp.conta.no`) proves it. A hardcoded host reports `registered: false` for a
   company that **is** registered — the worst available answer to a statutory question.
2. **`edelivery.tech.ec.europa.eu`, or the `B-<md5>` CNAME form.** Every pre-2025 tutorial and
   library README uses one or both. The CNAME form is NXDOMAIN everywhere already (0 of 6 tested);
   the EC zone still answered on 2026-09-08 and is being decommissioned at the Commission's
   discretion. Code written from a tutorial passes review, passes tests, and later returns an
   NXDOMAIN that looks exactly like "not registered".

**The SMP base URL is data, read fresh from the NAPTR on every uncached lookup.** The *zone* is a
constant; the *host* never is. Test 4 below is the test that catches this, so do not weaken it.
