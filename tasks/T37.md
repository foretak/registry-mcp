## 1. `core/models.py` — three widened fields, two new models, one new report field

**(1a) Widen `FiledDocument`** (D-042(h)). Add three fields, remove nothing:

```python
    category: str | None = None          # the register's own category, verbatim: "accounts", "mortgage", "gazette"
    type_code: str | None = None         # the register's own form code, verbatim: "AA", "CS01", "MR01"
    description_code: str | None = None  # the register's own description template key, verbatim, never resolved
```

`description_code`'s field description must say **why** it is the template key and not the resolved
sentence: the key states what was filed, the values state who, and only the first is company data
(D-042(e)(1)). `days_from_fee_point` stays on the model and is **`None` for GB** — Companies House
publishes `accounts.next_due` for the *next* period and no per-period historical due date, so the
datum the field is measured against does not exist for a past filing. Say that in `notes`, once,
when the block is built; do not leave it to inference and do not invent a due date from the
statutory rule (D-009).

**(1b) Two new models**, after `FilingHistory` and before the error section:

```python
class Charge(_Base):
    charge_id: str | None = None           # the register's own opaque handle; not fetchable through this API
    charge_number: int | None = None       # the register's sequence number for this company
    status: str | None = None              # the register's own word, verbatim: "outstanding", "fully-satisfied"
    is_outstanding: bool | None = None     # derived by table membership; None when the word is not in the table
    classification: str | None = None      # what kind of instrument, as the register describes it
    created_on: date | None = None
    delivered_on: date | None = None
    satisfied_on: date | None = None
    assets_charged: str | None = None      # the register's own particulars text
    obligations_secured: str | None = None # the register's own secured-details text
    contains_floating_charge: bool | None = None
    parties_entitled: list[str] = []       # names as the register publishes them; see the field description

class ChargeBlock(_Base):
    charges: list[Charge] = []
    total_count: int | None = None         # the register's own count, which may exceed len(charges)
    outstanding_count: int | None = None
    satisfied_count: int | None = None
    provenance: SourceRef
    notes: list[str] = []
```

`CompanyReport` gains `charges: ChargeBlock | None = None`, always present per D-004, `null` on
every country that is not asked. Both models into `__all__`.

Three rules inside that model, all testable:

- **`parties_entitled`, never `persons_entitled`.** The register's name asserts a natural person;
  ours does not. The field description must carry D-042(e)(3) in substance: this is a party to the
  company's own instrument, it is the only place in the product where a natural person's name can
  appear, it is **never** a lookup key, never indexed, never searchable and never logged (D-028(1),
  D-040). `grep -rn "persons_entitled" src/registry_mcp/core/` must return nothing.
- **`is_outstanding` is derived by membership of a committed table**, in `registries/gb/`, not in
  `core/` — which register words mean "live" is national vocabulary. A `status` word the table does
  not contain yields **`None`, never `False`** (D-025(d), D-011). Part A question 9 gives the table
  its rows; a word you did not observe does not go in it.
- **Two-level nullability, as D-026(c) and D-041(c) rule it.** Block **absent** = not requested, or
  the fetch failed (and a `notes` sentence on the report says which). Block **present with
  `charges: []`** = Companies House publishes charges for this entity and there are none. Those must
  never be able to collapse into each other, which is why D-042(d) makes an undeclared `include`
  value a `bad_request` and not an empty block.

## 3. `registries/gb/mapping.py` — build the two blocks

`map_filings(payload, *, cached, fetched_at) -> FilingHistory` and
`map_charges(payload, *, cached, fetched_at) -> ChargeBlock`.

**Filings.** Per item: `filed_at` ← `date`; `category` ← `category`; `type_code` ← `type`;
`description_code` ← `description` **verbatim**; `document_id` ← `transaction_id`;
`period_end` ← `description_values.made_up_date` **and no other key from that object**;
`kind` ← `"annual_accounts"` when `category == "accounts"`, `"confirmation_statement"` when
`category == "confirmation-statement"`, else `None` (`registries/gb/rules.py` already owns both
slugs as `ACCOUNTS_KIND` / `CONFIRMATION_KIND` — import them, do not re-spell them).
`period_start`, `days_from_fee_point` and `file_format` stay `None`. `financial_year_end` on the
block ← the newest `period_end` among `kind == "annual_accounts"` items, carried verbatim, ties
broken by the later `filed_at` (D-041(d)). `documents` sorted by `filed_at` descending.

**Charges.** Per item as §1(1b) maps it; `classification` ← `classification.description`;
`assets_charged` ← `particulars.description`; `obligations_secured` ← `secured_details.description`;
`contains_floating_charge` ← `particulars.contains_floating_charge`;
`parties_entitled` ← the `name` of each `persons_entitled` entry and **nothing else from that
object**. Block counts from the payload's own `total_count` / `satisfied_count`; `charges` sorted by
`created_on` descending, then `charge_number` descending.

**Truncation is disclosed on both** (D-042(j)): when the block's `total_count` exceeds the number of
rows returned, append a `notes` sentence to *that block* saying how many were returned, how many
exist, and naming the register's own URL for the rest. Silently returning 25 of 300 is the quiet
inaccuracy this project exists to avoid.
