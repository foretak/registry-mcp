Full read of the codebase. Write findings to `REVIEW.md` under `## T10`. Checklist, each item gets PASS / FAIL with a file:line:

2. A `registries/se/` stub can be added without editing `core/`, `api/`, or `mcp/` — actually add a throwaway stub, run tests, confirm `/v1/countries` and `list_countries()` pick it up, then delete it.

4. Every field in `CompanyReport` traces to a verified brreg field or is documented as derived.
5. Tests green on a clean checkout: `git clone . /tmp/clean && cd /tmp/clean && uv sync --all-extras && uv run pytest -q`.
6. `git grep -iE "(api[_-]?key|secret|token|password)\s*[=:]\s*['\"][^'\"]{8,}"` returns nothing; `.env` not tracked.
7. Every error `hint` names a concrete next action (a tool/endpoint to call, or "retry after N s").
8. Rate limiter and logging cannot crash a request (fault injection: make the SQLite path unwritable, calls still succeed).
9. `mypy --strict` and `ruff` clean.
10. Tool docstrings contain the `KEYWORDS.md` aliases.
