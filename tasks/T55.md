## A. The extractor — `registries/se/` and not `core/`

**One filler is not a shared abstraction.** D-044(a)'s rule is *measure first, then unify*, and
D-047(f) has just closed the only candidate second caller: Britain is out until after 1 April 2028 on
population, not on parsing. So the extractor lives in `registries/se/`, it is Swedish, and when a
second country ever needs one, **that** entry moves it.

### A1. The shape of the work

`GET /dokument/{id}` returns a **zip containing exactly one file**, an inline-XBRL XHTML (measured:
44,909–47,497 B zipped, 122,630–157,013 B unzipped). Not the iXBRL + XBRL + PDF triple Bolagsverket's
*submission* documentation describes — the värdefulla-datamängder endpoint serves the single original
document. Handle a zip with more than one entry by **reporting, not guessing**: pick nothing, raise
`upstream_error`, and say how many entries it had.

### A2. The one-line rule that carries the whole privacy story

> **Read `ix:nonFraction`. Never read `ix:nonNumeric`.**

Measured across six documents: **346 numeric facts, 0 of which is a name**, and every person-bearing
fact is an `ix:nonNumeric`. This is a **static property of the extractor's element filter**, and it is
tested as one — not as a per-concept blocklist, because Sweden **renamed its signature concepts
between the two taxonomy versions sampled** (`se-gen-base:UnderskriftArsredovisningForetradareTilltalsnamn`
→ `se-gen-base:UnderskriftHandlingTilltalsnamn`, and the matching `…Efternamn`) and a blocklist would
have gone stale silently. Write the rule as the module's first docstring paragraph and give the
renaming as the reason, so nobody "improves" it into a blocklist later.

### A3. `currency` comes from the unit. This is the thing that will be got wrong.

`FinancialPeriod.currency` is **required with no default** (D-043(d)), so a period whose currency
cannot be established is **dropped entirely**, not emitted with a guess. The source is:

```
ix:nonFraction/@unitRef  →  xbrli:unit[@id]  →  xbrli:measure  →  "iso4217:SEK"
```

**Never `se-cd-base:Redovisningsvaluta`.** It was renamed *and* re-typed between the two taxonomy
versions: the concept became `se-cd-base:RedovisningsvalutaHandlingList` and its value went from the
string `"SEK"` (2020, 2022) to the enum member `se-mem-base:ValutaSvenskaKronorMember` (2025). A
parser keyed on it builds **nothing at all** on the current taxonomy — and, worse, would have passed
review against a 2022 fixture. The unit route is version-independent and was measured so in both
countries. Assert it against the 2020 **and** the 2025 fixture, which differ in exactly this way.

### A4. Contexts, periods and signs

- **Zero dimensions in any K2 document sampled.** Every figure is an undimensioned fact under a single
  period. If a context carries `xbrldi:explicitMember` or `typedMember`, that is Part 0's stop
  condition, not something to handle quietly.
- **Two years are tagged in some documents** (the comparison column). Select the **latest** context by
  period end and take facts from it only. One line, and it is the difference between this year's
  balance sheet and last year's.
- **Signs are correct on losses as filed** (`Rorelseresultat` −43,649 etc.) — relay them, never
  normalise, never take an absolute value.
- **`@sign="-"` and `@scale` are iXBRL attributes and both must be applied.** Test a document that
  uses each; if none of your fixtures does, construct one by hand and say so.
- **An absent line is not a zero** (D-043(f)): `Anlaggningstillgangar` is absent on a company with no
  fixed assets and `LangfristigaSkulder` is absent in a year with none. `None`, never `0.0`.

### A5. Nothing is derived. Nothing at all.

D-043(e) refuses every derived indicator, and Sweden hands this task the strongest evidence in the
file for that refusal: the register's own taxonomy tags **`se-gen-base:Soliditet`**, the equity ratio,
and **the same company filed the identical quantity as `−0.1761` in its 2020 report and `−17.61` in
its 2022 report's comparison column** — both with `unitRef="procent"` resolving to
`xbrli:measure = pure`. Nothing in the document disambiguates the scale. **`Soliditet` and every other
ratio concept are not read, not mapped, not relayed, not logged.** No sum, no difference, no ratio, no
`is_solvent`, no year-on-year change. The one permitted comparison is D-043(e)'s: a `notes` caveat if
`total_assets` and `total_equity_and_liabilities` disagree — and the recon measured **18 of 18
identities reconciling exactly**, so if it ever fires, say so in your report.

`current_liabilities` and `non_current_liabilities` together to make `liabilities`**: D-043(e) forbids

Metadata:

- **`accounting_framework`** — `"K2"` or `"K3"`, from the **`link:schemaRef` href path**
  (`…/k2/risbs/2021-10-31/…`), never from a concept. National vocabulary in a value (D-004).
- **`scope`** — entity accounts, where the document says so. The K2 channel excludes
  koncernredovisning, so `consolidated` is `False` for a K2 document and that is a fact about the
  channel rather than an inference about the company; put the reason in `notes`. **For K3 it is
  `None` unless Part 0's document establishes otherwise** — nobody here has read a K3 filing, and
  D-011 forbids a value that would mean both "entity accounts" and "we did not check".
- **`document_id`** — the **same `dokumentId` the sibling `FiledDocument` already carries**. D-043(c)
  reserves the field for exactly this and here the two blocks genuinely share a handle; say so in the
  note so a caller can join them.
- **`period_start` / `period_end`** — from the selected context, not from the filename.
- `small_entity`, `audit_exempt`, `unaudited`, `liquidation_basis` — fill only from a fact you have
  actually read. `None` is the correct answer for anything the document does not say (D-011).

**`SourceRef`** — `source` names Bolagsverket's document service, `source_url` the exact `/dokument/{id}`
URL, `license` **D-038's existing Bolagsverket sentence, unchanged and reused verbatim**. It is already
a described regime rather than a name, which is what D-047(f) requires of a figure derived from a filed
document. **`"OGL"` never appears on this block, and neither does any invented licence name.**

## C. The fetch, and the request budget

- **`filings` and `financials` share the `/dokumentlista` fetch.** One key,
  `SE:bolagsverket:filings:{env}:{id}`, one upstream call (D-043(h)(1)), the key that already exists.
  **The hazard is D-043(h)(3) for the third time in this codebase**: `lookup_with` runs attachments
  concurrently, so a naive implementation makes two identical list calls on a cold cache and both
  succeed. **One shared in-flight result, and assert the request count** — do not assume it.
- **One `/dokument` fetch, for the most recent annual report only.** D-047(f) rules this: the register
  lists six for `5561890038`, one request each, against a 60/min budget shared with the token refresh.
  `notes` must say **how many annual reports the list reported, which period was parsed, and that the
  full list with dates and document ids is in `include=["filings"]`** — truncation disclosed, never
  silent (D-042(j)).
- **`registries/se/__init__.py`**: `supported_includes` gains `"financials"`, and the concrete
  `async def financials(self, id: str) -> FinancialSummary`.
- **Absent versus empty** (D-042(d)(3), D-011). A company whose `/dokumentlista` is empty — paper
  filer, IFRS preparer, handelsbolag, ekonomisk förening, bostadsrättsförening — gets an **absent**
  block plus a report-level `notes` sentence, **not** an empty `FinancialSummary`. A fetch or parse
  failure is likewise absent-plus-note, and **the lookup still succeeds** (D-042(b)).
- **`DEADLINE_INCLUDES` does not gain `financials`** — D-043(j). Assert it.

## D. `core/cache.py` — one row, and one hard rule

```python
"financials": (30 * 24 * 60 * 60, 60 * 60),
```

Key **`SE:bolagsverket:financials:{env}:{dokumentId}`** — **keyed on the document, not on the
company**, because an annual report is immutable once filed and a correction is a new filing with a
new id (D-047(f)). No collision with Norway, whose key is `NO:brreg:accounts:{orgnr}`, kind `accounts`.
Thirty days rather than "indefinitely": nothing here is cached forever, and the ceiling costs one
re-parse a month while capping how long a taxonomy-handling bug can outlive its fix. Put that in the
comment.

> **Hard rule: the zip and the XHTML are parsed and discarded in the same coroutine. Nothing writes
> the bytes, the document, or any `ix:nonNumeric` value to the cache, to a log, or to disk.** Only the
> parsed `FinancialPeriod` is stored. A cached iXBRL blob is a store of personal data with a retention
> policy nobody has written — D-028(2)'s clamp exists to stop exactly that, and it would arrive here
> without anyone deciding to build it. Assert it: a test that runs a fetch and then greps the cache
> payload for the string `nonNumeric` and for the document's own root element name.
