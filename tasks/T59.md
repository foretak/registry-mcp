What is **already** as cheap as it gets, so nobody spends time on it: tool results are compact JSON (no indent —
measured identical); every upstream is free; hosting is Railway's floor; Claude clients prompt-cache the tool list, so
the fixed cost is paid in full once per conversation and at a tenth thereafter.

Where the tokens go that could go elsewhere, measured:

- **The same content twice in `lookup_company`**: the attachments prose in the description (≈1,283 tokens) and the
  `include` schema description (≈645 tokens) explain the seven attachments twice.
- **The D-007 error paragraph three times**: `lookup_company` (293), `search_company` (180), `company_deadlines`
  (180) — near-identical text, plus the same sentence in `instructions`.
- **The country explanations** (what `NO`/`GB`/`SE` are, identifier shapes) repeated across `lookup_company`,
  `search_company`, `validate_company_id` and `company_deadlines` (not measured separately — measure it).
- **Stripping `null` keys** from results would save 7–30% per call (Tesco base 931 → 661; the full pull
  8,496 → 6,791) — but `null` is the contract's "the register does not say" and D-011/D-026(c) build on the
  present-`null` vs absent distinction, so this is a ruling, not a free win; the orchestrator's recommendation is **no**.

## Part 1 — Opus A: D-048, the token budget of the tool surface (writes `DECISIONS.md` and `tasks/T59.md` Part 2's exact list)

Rule on each, with the measurement beside the ruling:

(a) **The keyword rule stays; the repetition goes.** D-042(d)(2) says the block names and the retrieval words must
reach `lookup_company`'s *description*. Rule where each of the seven attachments is explained **once** — the
description keeps the words, the `include` schema description becomes the enumerated names with one clause each,
or the reverse — and state the test that pins the words (a test already asserts nine words in the description;
extend it, never weaken it).
(b) **One error paragraph, not three.** The D-007 contract (`invalid_id` → fix or search; `not_found` → search;
`unsupported_country` → `list_countries`; `bad_request` → read the hint; `upstream_*` → wait a minute) lives once,
in `instructions`, and each tool keeps one sentence pointing at it. Say whether the eval case that checks
error recovery (`evals/cases.json`) still passes on the words that remain.
(c) **Country explanations once.** The identifier shapes and register names belong on `lookup_company` (the tool
the model reads first) and `list_countries` (the tool that answers "what do you cover"); `search_company`,
`validate_company_id` and `company_deadlines` keep one line each.
(d) **The `search`/`fetch` aliases** (D-031, ≈1,180 tokens) exist for ChatGPT's connector contract and are dead weight
in every other client. Rule whether FastMCP can serve them only when the MCP `initialize` handshake's
`clientInfo.name` says ChatGPT (measure first: is `clientInfo` reachable from a `list_tools` handler in FastMCP
4.0.2?), or whether they stay for everyone. If they stay, their descriptions shrink to the D-031 minimum.
(e) **`filings` size**: 25 documents × 116 tokens is the largest single block. Rule on a default page smaller than
the cap with `notes` saying how many more exist — or leave the cap, on the ground that a caller who asked for
`filings` wants the history. State which. **`charges` stays as ruled by D-045(a)** — the free text is the answer.
(f) **`null` keys stay** (the orchestrator's recommendation, above); rule it so nobody proposes it again.
(g) **`SourceRef`**: `fetched_at` at second precision (drops the microseconds), nothing else — or nothing.
(h) **A budget, so it cannot creep back**: a test that fails when the sum of the seven tools' descriptions plus
`instructions` exceeds N tokens — counted with a local proxy (characters ÷ a measured ratio) since CI has no API
key; set N from the post-diet measurement plus 10%.
(i) **The quality gate for Part 2**, named exactly: `evals/run.py` golden mode (tool choice and arguments exact)
must stay 23 pass / 3 skip, and `--agent` mode on the same model as `evals/reports/2026-09-05-agent-run-2.md`
must not lose a case; the E19 hard gate (the model answers from memory without calling the tool) stays hard.
