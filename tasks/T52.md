# T52 — Recon: financial figures for Britain and Sweden out of the filed accounts themselves

Owner: Opus (researcher), dispatched by the orchestrator 2026-09-09 on Kim's "more depth". Worktree
`~/registry-mcp-wt/t52`, branch `t52`. Writes **one file**, `tasks/T52-recon.md`, in the style of
`tasks/T48-recon.md` (every fact `[fetched]`/`[search]`/`[repo]`, numbers counted, a verdict, the trap).

Why: D-043 shipped `include=["financials"]` for Norway because Regnskapsregisteret publishes parsed key figures;
D-043(i) records that Britain's and Sweden's figures exist **only inside filed documents** — Companies House's
iXBRL accounts behind the Document API, Bolagsverket's annual-report zip behind `GET /dokument/{id}` — and that
D-041(g) put document parsing out of scope *as a scope decision, not a register limit*. "Is this supplier
solvent" is the highest-ranked caller question the research found (`research/07-product-improvements.md`
item 14), and today it is answerable in one country of three. This recon establishes whether extracting the
D-043(c) figures (revenue, operating result, profit, total assets, equity, liabilities, period, currency,
accounting framework) from those documents is a bounded task or a project.

## The questions

1. **What is actually inside.** For each register: format (iXBRL XHTML? plain XBRL instance? PDF only for some
   companies?), the taxonomy and version (FRC/UK GAAP/IFRS taxonomies for Companies House; Bolagsverket's
   K2/K3/IFRS taxonomies — `se-gen-base`, `se-k2`?), whether the D-043(c) figures exist as tagged facts with
   stable concept names, and **how stable across companies** — sample the three documents per register and
   list, concept by concept, which of the ~20 D-043 figures each carries, with the exact tag names.
2. **Which companies have a machine-readable document at all.** Companies House: small companies file
   micro-entity/abridged accounts (fewer figures), some file PDF only (no iXBRL), dormant companies file nothing
   useful; find the register's own statement of the iXBRL share and the date it became mandatory for which
   population. Bolagsverket: T44 found Ericsson has **no** document in `/dokumentlista` while a small AB has six —
   establish from Bolagsverket's documentation which annual reports the digital channel carries (the T44 addendum's
   open question) and therefore which population a Swedish `financials` block could serve.
3. **The parsing cost.** Which Python library reads these (Arelle? `python-xbrl`? a bare XML parse of inline
   XBRL tags?), its licence, its size, whether it needs the taxonomy files downloaded (and their licence), and
   how long one parse takes. Prototype on the sampled documents in a scratch script (not committed): can the
   D-043(c) figures be pulled with a ~200-line parser that reads `ix:nonFraction` elements by concept name, or
   does it need a taxonomy-aware engine? Count what the prototype got right against the document's own totals.
4. **Cost per lookup and the cache.** Requests per `financials` call (filing history → document metadata →
   document: three for Britain; list → zip: two for Sweden), bytes, the Document API's rate limit and whether it
   counts against the 600/5-min key budget, Bolagsverket's 60/min. What a cached parse costs (store the figures,
   never the document — D-041(c) one fetch one `SourceRef`, and the licence of a *filed document* vs the register's
   metadata: quote both registers' terms on redistribution of filed documents, because the figures we relay are
   derived from the document, not from the register's own API).
5. **The person-bearing test (D-042(e)).** iXBRL accounts name directors, auditors, sometimes shareholders.
   A figure extraction relays numbers only — state exactly which tagged facts would be read and confirm none can
   carry a name (the `DirectorSigningFinancialStatements`-type concepts must never be read).
6. **The trap.** Name the one thing an implementer would get wrong (candidates: mixing consolidated and
   entity-only figures; the sign convention of liabilities; taking a prior-period column as current; assuming
   every company files iXBRL).

## Verdict

One of: **bounded** (a Sonnet task per country with the brief's shape sketched: footprint, models it reuses —
`FinancialSummary` must be the same block, D-042(g) — the parser's home, the TTL, the done-check), **project**
(what it would take and why it is not one task), or **not worth it** (the population it serves is too small or
the terms forbid it). Each with the evidence that decides it. The architect turns a "bounded" into a brief.
