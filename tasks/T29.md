## The change

1. **`core/models.py :: CompanyReport`** — two fields, both `default=None`:
   - `euid: str | None` in the identity block, directly after `id_scheme`. Description carries
     D-026(a)'s three traps verbatim in substance: not the LEI (register-issued, mandatory, EU-only,
     free — versus voluntary, global, LOU-issued, fee-bearing); "EUid" also names the European
     Digital Identity wallet, unrelated; not stable across a register reorganisation (encodes the
     register of origin). "Carried verbatim from the register; never constructed from parts."
   - `advertising_protected: bool | None` in the contact block, directly after `phone`. Description
     states the three values exactly as D-026(b): `True` = the register marks this entity as protected
     against direct-marketing use; `False` = the register publishes such a flag and it is not set;
     `None` = this register publishes no such flag (the default — never `False` by default). And the
     passer-on rule: when `True`, `notes` carries a plain-English sentence stating the protection, and
     that sentence must travel with any contact details passed on.
   - **Validator (D-020 precedent, architect's ruling for this task):** a model validator that raises
     `ValueError` when `advertising_protected is True` and no entry in `notes` contains the phrase
     `"direct marketing"` (case-insensitive). That phrase is the contract a country module must meet;
     say so in the field description. Sweden's N4 already contains it. This is what makes
     `CORE_ROADMAP_SPEC.md` §4's "a synthetic report with `advertising_protected=True` and no matching
     `notes` entry fails" true at runtime for every country, not only in fixtures.
2. **`registries/se/mapping.py`** — in the `reklamsparr` branch: `"JA"` → `advertising_protected=True`
   (N4 stays exactly as it is — it is the required sentence); `"NEJ"` → `False` (Sweden publishes the
   flag, so an explicit no is a real no); absent or blocked by `fel` → `None`. No other SE change.
   `euid` stays `None` for SE — Bolagsverket publishes none (D-036).
3. **`registries/se/rules.py :: rules_markdown()`** — the sentence that describes reklamspärr as a
   `notes`-only caveat now also names the field: "`advertising_protected` is `true`/`false` from
   Statistics Sweden's *reklamspärr* flag; when `true`, a `notes` sentence states it and must travel
   with any contact details passed on."
4. **`api/main.py :: _COMPANY_EXAMPLE`** — both keys, `null`, in model order. If a test asserts the
   example validates against `CompanyReport` or matches a fixture byte-for-byte, keep it green the
   way it is written, do not weaken it.
5. **Docs** — README example report and `static/llms-full.txt` example gain the two keys as `null`
   and one sentence each on what they mean; `server-card.json` only if it embeds the schema/example
   (find how it is kept in sync before editing by hand); `KEYWORDS.md` §SE and any place that says
   the advertising block is "notes only" now says field + note. `CHANGELOG.md` "Unreleased": one line
   — two new nullable keys on every company report, additive, no existing key changed.
6. **`legal/terms.md`** — one sentence, in the section about what passes to the user (the NLOD
   attribution paragraph is the model): where a register marks an entity as protected against

   record on and of you passing it on further — keep it with the contact details.
