## §1. `core/registry.py` — one concrete method (D-045(g))

Both surfaces today do `report = await registry.lookup(id)` then
`registry.deadline_report(report, today)`. Swapping in `lookup_with(id, include)` is **not
sufficient**, because D-043(j) restricts this operation: **`company_deadlines` accepts only include
values that can change a date — `{"filings"}` today — and anything else is `bad_request` naming
*the operation's* allowed set**, while `CountryInfo.supported_includes` keeps listing the country's
full set because it describes the country and not the operation. `lookup_with` validates against the
country's set and cannot produce that hint.

So `Registry` gains, beside `lookup_with`:

```python
DEADLINE_INCLUDES: frozenset[str] = frozenset({"filings"})   # module-level constant

    async def deadline_report_with(
        self, id: str, include: Sequence[str], today: date
    ) -> DeadlineReport: ...
```

which validates `include` against `self.supported_includes & DEADLINE_INCLUDES`, raises
`bad_request` whose `hint` and `details["allowed"]` name **that intersection**, then calls
`lookup_with(id, include)` and returns `self.deadline_report(report, today)`. `deadline_report`
itself is unchanged and `deadlines()` stays pure (D-018).

Do **not** validate in the surfaces (D-042(b): *"written per surface it drifts within a release"*),
and do **not** add an `allowed=` parameter to `lookup_with` — that gives one method two contracts
and puts the deadlines path's vocabulary into the lookup path's signature. Both declined by name in
D-045(g).

Note that `DEADLINE_INCLUDES` intersected with a country's set means **GB and NO get `filings` here
for free and it is a no-op for them** — that is `tasks/T37.md:280`'s GB requirement, satisfied by
construction rather than by a special case.

`GET /v1/{country}/company/{id}/deadlines` route, both calling `registry.deadline_report_with(...)`
